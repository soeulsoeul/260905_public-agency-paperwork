# 자연어 피드백 기반 프롬프트 개선 (Prompt Learning)

출처: [Arize-ai/prompt-learning](https://github.com/Arize-ai/prompt-learning) — Suzgun & Kalai(2024)의 메타프롬프팅을 확장해, 숫자 점수 대신 사람이 남긴 자연어 피드백으로 프롬프트를 반복 개정하는 기법.

## 언제 이 방법을 쓰는가

`eval-guide.md`의 이진(binary) 평가 루프는 재현 가능한 테스트 입력과 채점 기준이 있을 때 적합하다. 반면 이 문서의 방법은 다음 상황에 맞다.

- 부서장·검토자가 초안에 대해 "이 부분이 부족함", "이런 형식으로 써 달라" 같은 **자연어 코멘트**만 남기고, 이진 평가표는 아직 없을 때.
- 코멘트가 산발적으로 쌓여 있어(결재 반려 사유, 회의 중 지적, `reflect` 스킬이 기록한 학습 등) 이를 하위 에이전트 규칙에 반영하고 싶을 때.
- 정식 autoresearch 루프(run→score→mutate)를 시작하기 전, 우선 소규모로 피드백을 정리해 프롬프트를 다듬고 싶을 때.

두 방법은 배타적이지 않다. 자연어 피드백으로 먼저 규칙을 다듬은 뒤, 안정되면 `eval-guide.md` 기준의 이진 평가로 전환해 autoresearch 루프를 돌리는 순서를 권장한다.

## 3단계 루프 (원 논문·SDK 구조)

1. **Agent** — 현재 프롬프트(`.claude/agents/<name>.md`)로 하위 에이전트가 결과물을 만든다.
2. **Evaluator** — 사람 또는 검토자 역할 서브에이전트가 결과물의 문제를 자연어로 짚는다(수치 점수가 아니라 문장).
3. **Meta Prompt** — 그 피드백을 근거로 프롬프트·규칙을 개정한다. 근거 없는 피드백 한 건으로 규칙을 바꾸지 않고, 반복되는 지적만 반영한다.

## 이 프로젝트에서의 적용 절차

1. **피드백 축적**: 결재·검토 과정에서 받은 코멘트를 `(입력 요약, 산출물 요약, 피드백)` 3열 표로 모은다. 개인정보·비공개 내용은 요약·마스킹 후 기록한다. `reflect` 스킬이 남기는 `docs/solutions/**` 항목과 중복되면 그쪽을 우선 참조한다.
2. **패턴 확인**: 같은 지적이 3회 이상 반복되는지 확인한다. 1~2회의 개별 의견은 특이사항으로 남기고 규칙화하지 않는다.
3. **규칙 반영**: 반복되는 지적을 `.claude/agents/<name>.md`의 "작업 규칙" 항목에 짧은 규칙 문장으로 추가하거나 기존 문장을 교체한다. `Edit` 도구로 변경하고, 기존 산출물 형식·승인 절차·안전 규칙은 건드리지 않는다.
4. **검증**: 다음 유사 요청에서 지적이 재발하지 않는지 확인한다. 재발하면 규칙 문장이 모호했다는 뜻이므로 더 구체적으로 다시 쓴다.
5. 이 절차는 세션 내에서 Claude Code가 직접 수행하며, 외부 API 호출이나 별도 SDK 설치가 필요하지 않다.

## 실제 SDK(`prompt-learn` CLI/Python 패키지)를 쓰고 싶다면

원 저장소는 OpenAI/Google API와 CSV 형식의 `input/output/feedback` 데이터셋으로 프롬프트를 자동 개정하는 CLI(`prompt-learn optimize`)와 SDK(`PromptLearningOptimizer`)를 제공한다. 이 템플릿에는 기본 포함하지 않는다 — 설치·보안 검토 절차는 `docs/prompt-learning-sdk-setup.md`를 먼저 확인한다. 특히 데이터셋에 실제 민원인·개인정보를 넣지 않아야 하며, 외부 API로 데이터를 보내는 행위는 `docs/security-policy.md`의 승인 대상이다.
