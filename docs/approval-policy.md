# 승인 정책

## 기본 원칙

에이전트의 초안·분석·제안은 자동 실행 권한이 아니다. 아래 행위는 담당 공무원 또는 전결권자의 명시적 승인을 받은 뒤에만 실행한다.

| 행위 | 예시 | 최소 승인권자 | 에이전트 처리 |
| --- | --- | --- | --- |
| 대외 발송 | 이메일, 문자, 보도자료, 민원 회신, 공문 | 업무 책임자 | 발송안과 수신 대상을 제시하고 대기 |
| 결재·상신 | 전자결재 기안, 승인, 반려 | 기안자/전결권자 | 초안만 생성 |
| 시스템 쓰기 | DB 수정, 파일 업로드, 티켓 생성, 일정 등록 | 시스템 소유 부서 | 변경안·영향 범위 제시 후 대기 |
| 원본 변경·삭제 | 기록물 수정, 파일 삭제, 데이터 정정 | 기록물/데이터 책임자 | diff 또는 백업안만 제시 |
| 금전·계약·인사 | 지출, 계약 문서, 인사 조치 | 법정·내부 권한자 | 분석·초안만 제공 |
| 개인정보·비공개 정보 반출 | 외부 LLM·MCP·메일 전송 | 개인정보/보안 책임자 | 최소화·마스킹·승인 없이는 차단 |

## 승인 요청 형식

```text
[승인 요청]
목적:
실행할 작업:
대상 시스템/수신자:
입력·전송되는 데이터 등급:
변경 또는 발송 내용 요약:
영향과 되돌리기 방법:
대안:
승인자:
```

승인은 작업별로 기록한다. 포괄적·구두 승인을 반복 실행 권한으로 해석하지 않는다. 긴급 상황은 기관의 비상대응·전결 규정을 따른다.
