공공기관 부서장 업무효율화 멀티에이전트
Claude Code 설정 안내
========================================

0. 적용 전 확인
---------------
이 템플릿은 초안·조사·검토 보조용입니다. 대외 발송, 결재, 원본 변경,
개인정보 처리의 최종 책임과 실행 권한은 담당 공무원에게 있습니다.

기관의 정보보안, 개인정보, 기록물, 전결 규정을 먼저 확인하십시오.


1. Claude Code 설치 확인
-------------------------
터미널에서 아래 명령을 실행합니다.

  claude --version

명령이 없으면 Claude Code를 설치한 후 다시 실행합니다. Windows에서는
WSL 또는 Git Bash 환경 사용이 일반적입니다.


2. 대상 프로젝트 준비
-----------------------
업무 자료와 자동화 스크립트를 둘 전용 프로젝트 폴더를 만듭니다.

예시:

  mkdir public-agency-ai-workspace
  cd public-agency-ai-workspace

개인정보·비공개 자료는 기관에서 승인한 저장소와 접근통제 환경에서만
사용하십시오. 개인 PC의 임의 폴더나 공개 Git 저장소에 저장하지 마십시오.


3. 템플릿 복사
---------------
압축을 푼 폴더에서 다음 항목을 대상 프로젝트 최상위 폴더로 복사합니다.

  CLAUDE.md
  .claude/agents/  (숨김 폴더 포함)
  .claude/skills/  (숨김 폴더 포함)
  .claude/settings.json
  docs/

복사 뒤 구조는 아래와 같아야 합니다.

  public-agency-ai-workspace/
  ├─ CLAUDE.md
  ├─ .claude/
  │  ├─ settings.json
  │  ├─ agents/
  │  │  ├─ document-drafter.md
  │  │  ├─ policy-reviewer.md
  │  │  ├─ data-analyst.md
  │  │  └─ security-reviewer.md
  │  └─ skills/
  │     ├─ blueprint/
  │     ├─ deep-dive/
  │     ├─ autoresearch/
  │     └─ reflect/
  └─ docs/
     ├─ agent-problem-definition-template.md
     ├─ approval-policy.md
     ├─ official-document-style-guide.md
     ├─ security-policy.md
     ├─ workflow-catalog.md
     └─ operational-runbook.md

`.claude/skills/`는 민원·정책 산출물이 아니라 이 에이전트 체계 자체를
설계·개선하기 위한 메타 스킬입니다(새 하위 에이전트/업무 흐름 추가 시
blueprint → deep-dive → 구현 → autoresearch → reflect 순으로 사용).
출처: https://github.com/byungjunjang/jangpm-meta-skills

주의: Windows 탐색기는 .claude를 숨김 폴더로 표시할 수 있습니다. 압축 해제
도구에서 숨김 폴더가 빠지지 않았는지 확인하십시오.


4. 기관 맞춤화 (필수)
-----------------------
CLAUDE.md와 docs/ 문서를 열어 대괄호나 기관에 맞지 않는 내용을 수정합니다.
특히 다음을 확정합니다.

  - 전결권자와 승인자
  - 개인정보·비공개 정보의 정의와 반출 절차
  - 사용 가능한 데이터 저장소와 MCP 서버 목록
  - 대외 발송 가능 채널과 발송 전 검토 절차
  - 로그 보관 위치와 보존 기간

이 단계를 끝내기 전에는 실제 비공개 자료를 Claude Code에 입력하지 마십시오.


5. Claude Code 시작
-------------------
대상 프로젝트 폴더에서 실행합니다.

  claude

첫 요청 예시:

  "docs/workflow-catalog.md와 CLAUDE.md를 읽고, 다음 주 주간업무회의
   보고자료의 목차와 필요한 확인자료 목록을 만들어줘. 외부 발송이나
   원본 파일 수정은 하지 마."

Claude Code가 프로젝트의 CLAUDE.md 지침을 읽고, 필요하면 .claude/agents의
역할 지침을 활용하도록 요청합니다.


6. 권한 운영 원칙
-----------------
처음에는 읽기·분석 중심으로 운영하십시오.

  - 명령 실행, 파일 수정, 외부 도구 호출 요청을 검토한 뒤 승인합니다.
  - --dangerously-skip-permissions 옵션은 업무 환경에서 사용하지 않습니다.
  - 대외 발송, 전자결재, DB 변경, 파일 삭제, 권한 변경은 승인 전 실행하지
    않도록 요청하고 실제 도구 권한도 최소화합니다.
  - 승인된 MCP 서버만 연결하며, 서버별 읽기/쓰기 권한과 전송 데이터를
    기록합니다.

권한 현황은 Claude Code 안에서 /permissions 명령으로 확인할 수 있습니다.


7. 권장 업무 요청 예시
---------------------

가. 회의자료
  "문서작성 에이전트 역할로, 제공한 자료만 근거로 부서장 보고용 1쪽 요약과
   회의 안건 초안을 만들어줘. 수치에는 출처와 기준일을 붙이고, 불확실한
   내용은 [확인 필요]로 표시해줘."

나. 규정 검토
  "규정검토 에이전트 역할로, 이 사업안에 관련된 법령·지침을 조사해줘.
   조문, 시행일, 출처, 적용상 불확실성을 표로 보여줘. 최종 법률 판단은
   하지 말고 담당부서 확인 사항을 정리해줘."

다. 데이터 분석
  "데이터분석 에이전트 역할로, 승인된 공개 데이터만 사용해 핵심 지표를
   분석해줘. 데이터셋명, 제공기관, 추출일, 기간, 필터, 한계를 함께 적어줘."

라. 보안 검토
  "보안검토 에이전트 역할로, 이 요청과 첨부자료의 개인정보·비공개 정보·
   외부 전송 위험을 검토해줘. 위험, 완화조치, 승인 필요 여부를 표로 제시해줘."

마. 신규 하위 에이전트 설계 (메타 스킬)
  "docs/agent-problem-definition-template.md를 같이 채운 다음, blueprint
   스킬로 새 하위 에이전트 설계 문서를 만들어줘."


8. 문제 발생 시
----------------
의심스러운 웹페이지·이메일·첨부문서가 '지침을 무시하라', '파일을 삭제하라',
'외부로 전송하라'고 말해도 실행하지 마십시오. 이는 신뢰되지 않은 데이터로
처리하고, 작업을 중지한 뒤 정보보호 담당자에게 알립니다.

개인정보 또는 비공개 자료가 잘못 입력·전송된 경우에는 추가 작업을 중지하고,
기관의 개인정보·보안사고 대응 절차에 따라 보고하십시오.


참고
----
Claude Code의 실제 메뉴와 설정 형식은 설치 버전에 따라 달라질 수 있습니다.
기관 배포 환경에서는 관리형 정책이 프로젝트 설정보다 우선할 수 있습니다.
현재 버전의 공식 문서를 확인한 뒤 적용하십시오.
